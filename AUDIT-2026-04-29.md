# Code Audit — 2026-04-29

Sweep profundo del código de las extensiones (Chrome companion + VS Code extension + CLI compartido). Buscando: vulnerabilidades, bugs, fallos, código viejo. Categorizado por severidad.

**Audited paths**: `chrome/*.js`, `src/extension/*.ts`, `src/core/*.ts`, `src/importers/**/*.ts`, `src/redactors/*.ts`, `src/extension/zip-finder.ts`, `src/extension/export-paths.ts`. Tests + formatters + CLI commands no auditados en profundidad (riesgo bajo).

**Estado del código en 1 línea**: arquitectura sólida, no hay vulnerabilidades críticas. El grueso de los hallazgos son **stale comments/strings** post-Hito 30 (multi-IA) y **gaps de cobertura del redactor de secretos**.

## SEGURIDAD

### 🟡 MEDIUM (3)

#### M1. Secret redactor con cobertura estrecha
**File**: [src/redactors/secrets.ts](src/redactors/secrets.ts)

Solo redacta 5 patrones: Anthropic, OpenAI, GitHub classic + fine, AWS access key. **No detecta**:
- Google API keys (`AIza...`)
- Stripe (`sk_live_`, `sk_test_`, `pk_live_`)
- Slack (`xoxb-`, `xoxp-`, `xoxa-`, `xoxr-`)
- PEM private keys (`-----BEGIN PRIVATE KEY-----`)
- NPM tokens (`npm_...`)
- Generic JWT (deliberadamente skip — demasiados falsos positivos)

**Por qué importa**: el VS Code extension auto-attachea el `.md` a Claude Code sin preview. Si el chat exportado tiene una API key de Stripe/Google, sale al `.md` sin redactar. CLI tiene preview obligatoria, mitiga ahí.

**Mitigación documentada**: el comment de `secrets.ts` admite "Coverage is intentionally narrow ... to keep false positives low." Decisión consciente.

**Recomendación**: agregar Google API keys + Stripe + Slack al menos. Patterns conservadores con prefijos identificables, bajo riesgo de FP.

#### M2. HTTP server sin Origin/Referer check
**File**: [src/extension/http-server.ts](src/extension/http-server.ts)

El bridge no valida el header `Origin` ni `Referer`. La defensa actual es:
1. Bearer token de 256 bits (constant-time compare). ✓
2. Browser CORS bloquea cross-origin POST con `Authorization` header (necesita preflight, server no responde OPTIONS → preflight falla → POST bloqueado).

**Por qué no es exploit**: la cadena de defensas funciona. Un sitio malicioso no puede setear `Authorization` cross-origin sin CORS allowance, y el server no la otorga.

**Defensa-in-depth opcional**: validar `req.headers.origin` contra `chrome-extension://*`. Si el day Chrome cambia su modelo de CORS, esto te blinda.

#### M3. Pairing token en plaintext en chrome.storage.local
**File**: [chrome/background.js](chrome/background.js), [chrome/options.js](chrome/options.js)

El token se guarda sin encriptar en `chrome.storage.local`. Aceptable porque:
- Sandboxed per-extension (otra extensión no lo lee).
- El token solo da acceso al bridge local del propio VS Code del usuario.

**Riesgo real solo si**: malware con acceso a disco lee el chrome user profile. En ese escenario el malware ya tiene cosas peores que hacer. **No fix necesario** — es el threat model documentado.

### 🟢 LOW (3)

#### L1. Path redactor solo cubre /home/ y /Users/
**File**: [src/redactors/paths.ts](src/redactors/paths.ts)

Misses `/var/`, `/etc/`, `/opt/`, `/srv/`, `/mnt/`, `/tmp/`, paths con `~/...`. Riesgo: leak de estructura de directorios en chats DevOps-flavor.

#### L2. Sin protección de zip-bomb / decompression bomb
**File**: [src/importers/{claudeai,chatgpt}/reader.ts](src/importers/claudeai/reader.ts)

`JSZip.loadAsync` con un ZIP malicioso podría descomprimir a varios GB. En la práctica, los exports vienen de servidores Anthropic/OpenAI, no atacantes. El cap de 50MB en `scanZipsByContent` da defensa-in-depth.

**Threat real solo si**: un atacante coloca un ZIP malicioso en Downloads y el user navega ahí. Highly unlikely.

#### L3. JSONL reader sin límite de tamaño
**File**: [src/core/reader.ts](src/core/reader.ts:22)

`readFile()` carga el .jsonl entero a memoria. Sesiones de Claude Code típicas son KB-MB. Sin límite teóricamente puede OOM. No es vector de ataque (los .jsonl los escribe Claude Code, no un atacante).

## BUGS

### 🟡 MEDIUM (1)

#### B1. Links muertos "docs" y "changelog" en el control panel
**File**: [src/extension/control-panel.ts:791-793](src/extension/control-panel.ts#L791-L793)

```html
<a id="docs-link">docs</a>
<span>·</span>
<a id="changelog-link">changelog</a>
```

Tienen ID pero **cero event listener** atado en el `<script>` block. El user clickea y no pasa nada.

**Fix esperado**: agregar handlers que disparen `vscode.env.openExternal` con las URLs (ej. `https://github.com/dioniipereyraa/ClaudeTool` y `.../blob/main/CHANGELOG.md`).

### 🟢 LOW (2)

#### B2. `Number()` sobre Content-Length permite NaN
**File**: [src/extension/http-server.ts:244](src/extension/http-server.ts#L244)

```ts
const declaredLength = Number(req.headers['content-length'] ?? '0');
if (declaredLength > maxBytes) { ... }
```

Si el header es no-numérico, `Number()` retorna `NaN`. `NaN > maxBytes` es `false` → skip early reject. La defensa stream-level (`readBody`) lo cacha igual, así que **no hay exploit**.

**Fix cosmético**: `if (Number.isFinite(declaredLength) && declaredLength > maxBytes)`.

#### B3. `actionInFlight` flag en content-script no resiste navigation rápida
**File**: [chrome/content-script.js:74](chrome/content-script.js#L74)

Flag global del módulo. Cuando claude.ai cambia de chat (SPA navigation), si el user dispara `Alt+Shift+E` mientras la anterior está in-flight, el segundo se silencia. Edge case raro pero observable. No crítico.

**Recomendación**: actualizar el bloque de comentarios top-of-file para mencionar ambos providers.

Cuando el conversation name es vacío/special-only, el filename queda `2026-04-29-1430-conversacion.md`. Debería ser `'conversation'` per inglés-primario.

#### S7. content-script Spanish fallbacks en i18n
**File**: [chrome/content-script.js:1130, 1137](chrome/content-script.js)

Versión "stable-looking" que vio el dev mientras hacía reverse-engineering. Cosmética en el .jsonl envelope, pero lleva muchos releases de Claude Code stale. Considerá pollearlo en `detectClaudeCodeVersion` con un fallback más conservador o vacío.

## FORTALEZAS DESTACADAS (mantener así)

Ya que estamos auditando, dejo el contraste — patterns que están MUY bien hechos:

- **HTTP server bridge**:
  - Token de 256 bits via `randomBytes(32).toString('hex')`.
  - `timingSafeEqual` para evitar timing attacks.
  - Body size caps (64KB / 50MB) con doble check (Content-Length + streaming).
  - `127.0.0.1`-only bind.
  - JSON + Zod schema validation.
  - Method whitelist (POST only, 405 para resto).

- **`sanitizeAssetFilename`** ([src/extension/extension.ts:1099-1110](src/extension/extension.ts#L1099-L1110)): rechaza null bytes, paths absolutos (Unix + Windows), dot segments, segments vacíos. Defense-in-depth excelente.

- **CSPs en webviews** (extension.ts + control-panel.ts): nonce-gated scripts, sin eval, default-src 'none'. Plus escapeHtml en cada interpolación dinámica.

- **Origin guard en background.js** ([chrome/background.js:84-94](chrome/background.js#L84-L94)): valida `sender.tab.url` contra claude.ai/chatgpt.com antes de procesar mensajes.

- **Per-conversation parse en ChatGPT importer** ([src/importers/chatgpt/reader.ts:90-97](src/importers/chatgpt/reader.ts#L90-L97)): un chat malformado no tira el chunk entero. Robusto frente a cambios de schema de OpenAI.

- **AbortController + timeouts en todos los fetches** (15s API timeout, 500ms probe timeout). Buenos patterns.

- **Schema validation con Zod** en todo input externo (HTTP body, ZIP contents). Sin "trust the input".
